# BillFlow AI: project status

## Completed (verified by tests or live HTTP checks)

- Organisation-scoped data model in SQLite (organisations, users, client companies, vendors, source documents,
  invoices, invoice line items, approvals, audit events) with foreign keys, uniqueness and indexes.
- First-run owner account created from environment variables; weak passwords refused.
- Login and logout; PBKDF2-SHA256 password hashing; signed HttpOnly SameSite=Strict sessions; login lockout.
- CSRF protection on every state-changing request.
- Role permissions (owner, administrator, accountant, reviewer) enforced server-side.
- Organisation isolation tested for reads, writes, downloads, exports, client attachment and audit visibility.
- Client company creation with GSTIN format and checksum checks.
- Upload of PDF, JPG, JPEG and PNG (raw body with `X-Filename`), validated by content, size-limited, stored privately.
- PDF text extraction (pypdf) into a Pydantic schema with per-field confidence and page references.
- Image OCR through Tesseract when the executable is present; otherwise the file is flagged for manual entry.
- Scanned PDFs without text are flagged as unreadable, not as extracted.
- Deterministic validation: GSTIN format and checksum, invoice number and date, taxable and total arithmetic,
  CGST/SGST and IGST consistency, rounding tolerance, line-item arithmetic.
- Duplicate detection: identical file hash, and exact or possible duplicates by client, supplier GSTIN, invoice
  number, date and total.
- Review screen with two panels (original document, extracted fields with confidence, validation, line items).
- Corrections stored separately from original extraction; each field change audited with previous and new values.
- Approve, reject, mark for review, reopen, and re-run extraction. Approval blocked by errors or exact duplicates.
- CSV export of approved invoices (invoice level and line level). Invoice export marks invoices as exported.
- Audit history page; duplicates, validation exceptions, vendors, export centre, users and settings pages.
- Synthetic GST invoices generated by `scripts/synthetic_invoices.py`, and a seed script for labelled demo data.

## Known limitations

- Not production-secure. See `docs/SECURITY.md`.
- Rule-based extraction is tuned to text layouts like the synthetic invoices. Real invoices will often miss fields;
  every extraction needs review.
- GSTIN checks are format and checksum only. They do not check the GST portal.
- No AI provider is connected. The AI-provider interface exists in `app/services/ai_provider.py` with a null implementation.
- Synchronous uploads. SQLite is single-writer. Login lockout is per process.
